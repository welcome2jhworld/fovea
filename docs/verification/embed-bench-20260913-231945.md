# Embedding lane benchmark and sanity check 2026-09-13T23:19:45Z

M4 worker check for the two initial index versions, `siglip2-b16-224` and
`qwen3vl-emb-2b-1024`: per-frame cost, query cost, load and memory with the
committed `embed-bench` CLI, a retrieval sanity check with `embed-query` on
frames of three local videos, an HTTP run through `fovea-worker serve`, and a
check that the worker's index version hash equals the hash Qt computes for the
same descriptor. These are not the M4 evaluation metrics (that is
`scripts/eval_search.py` on the question set).

The index version hashes in this report are the ones from before the review
fix that added the image-processor class to both descriptors; the cost, memory
and retrieval numbers are unaffected, and the current hashes are in the
evaluation reports next to this file.

Machine: Apple M4 (10 cores), 16 GB, macOS 26.3 arm64, MPS. Worker venv:
Python 3.12.8, torch 2.14.0, transformers 5.17.0, qwen-vl-utils 0.0.14, Pillow
12.3.0, numpy 2.5.3. Weights were already in the Hugging Face cache
(google/siglip2-base-patch16-224 at 75de2d55ec2d0b4efc50b3e9ad70dba96a7b2fa2,
Qwen/Qwen3-VL-Embedding-2B at 9f2f7e710d6d81056aa5c0a4f04764fec6bb7bda). The
machine was shared with other work during every run (other lanes' builds and
tests, a desktop app; 1-minute load average 1.9 to 4.8, about 3.9 GB of swap in
use), so absolute times are noisy.

## embed-bench

```
worker/.venv/bin/python -m fovea_worker.cli embed-bench <frames> --index <name> [--batch B] [--repeat R]
```

One warmup batch is excluded; per-frame ms is batch wall time / batch size over
full batches only (JPEG decode, preprocessing, model and copy to CPU included);
query ms is one text per call, 4 queries x 5 repeats after one warmup call.
Import ms is `import torch, transformers`; load ms is processor and model load
to the device. Peak RSS is the process maximum (on MPS it includes the transient
CPU copy of the weights during load); device memory is
`torch.mps.driver_allocated_memory()` at the end.

| Index version | Batch | Frames timed | Per frame p50 / p95 / mean ms | Compute s per footage hour at 1 sample/s | Query p50 / p95 ms | Import / load / first batch ms | Peak RSS MB | MPS memory MB |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| siglip2-b16-224 | 16 | 192 (6 batches x 2 passes) | 25.1 / 26.4 / 25.1 | 90.4 | 11.6 / 12.2 | 1859 / 3723 / 917 | 992 | 2736 |
| qwen3vl-emb-2b-1024 | 16 | 96 (6 batches) | 794.8 / 826.4 / 791.9 | 2850.8 | 72.8 / 135.7 | 1866 / 5705 / 12359 | 9013 | 6027 |
| qwen3vl-emb-2b-1024 | 4 | 112 (28 batches) | 883.5 / 1209.1 / 942.0 | 3391.2 | 89.2 / 118.6 | 2260 / 6823 / 3746 | 9013 | 4953 |
| qwen3vl-emb-2b-1024 | 2 (the lane's batch) | 114 (57 batches) | 932.6 / 1102.9 / 957.9 | 3448.4 | 86.4 / 112.2 | 1843 / 7977 / 2404 | 7375 | 4953 |

Vector bytes per frame: 3072 raw float32 (3088 per VectorStore record, 4096
base64) for SigLIP 2; 4096 raw (4112 per record, 5464 base64) for Qwen3-VL at 1024
dims.

Reading:

- SigLIP 2 indexes one camera at 1 sample/s at about 40x real time.
- Qwen3-VL-Embedding at the lane's batch of 2 costs 958 ms per frame on average,
  just under the 1 s per sample budget on this shared machine (3448 s of compute
  per footage hour). Batch 16 is 17% cheaper but would hold the lane for up to
  13 s per 16 frames; batch 4 was within noise of batch 2.
- Earlier exploratory runs with a scratch script using the same model calls
  (not the committed CLI) informed the preprocessing choice: at the model
  repository's full resolution (960x544, 510 visual tokens, float16, batch 16)
  a frame cost 1568 to 1619 ms; at max_pixels 262144, 755 to 772 ms. The vision
  tower was about half of that (360 to 383 ms). Eager attention was slower
  (1027 to 1060 ms); bfloat16 ran at the same speed as float16.
- dtype: on the model card's text example (four queries against one document,
  instruction "Represent the user's input.") MPS float32 reproduced the card's
  similarities exactly (0.8158, 0.5195, 0.3884, 0.1093), float16 was within
  0.0002 (0.8159, 0.5196, 0.3885, 0.1095) and bfloat16 within 0.0031 (0.8164,
  0.5165, 0.3874, 0.1063), so float16 is used on MPS. Float32 load took 31 s and
  about 8.5 GB and was not used.

Result: Qwen3-VL-Embedding ranked the expected video first for all six positive
queries, Korean and English. SigLIP 2 ranked it first for four of six; both
white car queries ranked lot-walking first. That is not clearly wrong: frame
lot-walking/0015 shows a white car (checked by viewing the frame), so the
expectation is ambiguous for this corpus, and SigLIP 2's margin between the two
lots is small (0.1585 vs 0.1450). The red truck queries returned lot-car frames
with a red car for both versions (lot-car/0016, 0018 and 0019 viewed: each shows a red sedan). Their top
scores are below every positive query's top score for the same version (SigLIP 2
0.0899 and 0.0762 vs at least 0.1313; Qwen3-VL 0.4424 and 0.4767 vs at least
0.5132), but no threshold was tuned and three videos say nothing about
calibration. Qwen3-VL scores for the same query differed in the fourth decimal
between two runs (0.6695 then 0.6693), consistent with float16 MPS kernels not
being bitwise deterministic.

Cost of these runs: SigLIP 2 embedded the 117 frames in 3831 ms and the 8
queries in 315 ms; Qwen3-VL in 96712 ms and 564 ms (batch 16 in the CLI).

## Through serve (HTTP)

A scratch client started `fovea-worker serve --backend dry --detector dry
--embedder transformers --embed-preload siglip2-b16-224,qwen3vl-emb-2b-1024
--exit-on-stdin-eof` the way `bench-serve` does and sent jobs one at a time:

| Step | Result |
| --- | --- |
| preload both versions | ready after 17.2 s (siglip2 load 5336 ms, qwen3vl 9110 ms, run in sequence) |
| siglip2 embed_frames, 16 frames | 200 ok, count 16, dims 768, 0 contract violations, 1468 ms (first image batch after a text-only warmup) |
| siglip2 embed_text | 200 ok, index_version `f423de902f45` (same as frames), 212 ms round trip |
| qwen3vl embed_frames, 16 frames | 200 ok, count 16, dims 1024, 0 violations, 16734 ms (the warmup embeds only a text, so image kernels compile here: the slowest 2-frame batch took 2459 ms per frame) |
| qwen3vl embed_text | 200 ok, index_version `499eba177997`, 140 ms |
| qwen3vl embed_frames, 32 frames, and 3 s later a qwen3vl embed_text with a 3000 ms deadline | query: 200 ok in 433 ms round trip (256 ms processing) while the index job was running (embed_busy_ms 3006 when the query was sent); index job: 200 ok, 32 vectors, 0 violations, 30955 ms |
