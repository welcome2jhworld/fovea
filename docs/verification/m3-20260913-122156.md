## Defects found and fixed while verifying

- After any core restart every analysed frame was unknown with
  `encode_failed: cannot write <frame>.jpg`. Cameras load (and create their
  spool directories) before the scheduler starts, and the scheduler's startup
  spool cleanup then deleted those directories. Found by the first run that
  analysed frames after a restart (a report of that run was discarded); the
  encoder now creates the directory when it writes.
- A camera whose analysis stopped and resumed (analytics or the camera switched
  off and on) restarted its generation at 1 while its rules' evaluators had
  accepted higher generations, so every later result would have been stale.
  Found by reading the code; generations now outlive the camera's scheduler
  state, and the extra scenario above checks it.
- The "detector below 0.67 detections/s" warning fired during a source outage;
  it now requires frames to be arriving.
- Script issues found on the way: the analytics toggle ran before the
  measurements and reset the camera's counters, and the restart check passed
  with no open events; both were reordered and tightened before this run.
